# 前端客户端 / 管理端隔离 — 设计文档

## 意图与为什么
内部演示/自己跑的电商智能客服系统。当前聊天页(顾客端)与管理后台共用一条顶部导航，两端混在一起，且导航在每个 HTML 里手抄、已发生漂移(`kb.html`/`review.html` 漏了「主题分布/验收」入口)。要把聊天页隔离成纯客服界面，管理后台收进独立外壳，两端在导航与视觉上可区分。

## 目标 / 非目标 / 反目标
- **目标**：聊天页去掉后台导航、变回纯客服界面；管理端用统一侧栏(单一导航源)；两端视觉可区分；后端零改动。
- **非目标**：不做登录/鉴权(内部演示)；不改路由与 API；不改聊天逻辑。
- **反目标**：顾客端不残留任何后台入口(除一个不显眼的「管理后台」链接)；不再保留多处手抄导航。

## 约束
- 纯静态前端(无框架、无构建)，沿用现有 `style.css` / `kb.css` 与 JS 注入方式。
- 后端不动：`app/main.py` 的路由与 `StaticFiles` mount 原样。
- 内部演示，无鉴权需求。

## 方案
- **A(采用) 集中式管理端外壳**：新建 `admin-shell.js` 统一生成管理端侧栏，各管理页只标记 `data-page`；聊天页删导航 + 侧栏底部加「管理后台」。根治导航重复与漂移。
- **B(不采用) 逐页删链接**：改动最小，但保留手抄导航与漂移隐患，治标不治本。

## 改动点
1. `static/index.html`：删除顶部 `topnav`；侧栏底部加「管理后台 →」小链接(指向 `/admin`)。
2. 新建 `static/admin-shell.js`：读取 `body[data-page]` 生成统一侧栏——顶部「← 返回聊天」+ 后台总览/知识库/待审队列/主题分布/验收 五项，并加「管理端」标识。
3. 管理页(8 个)换共享外壳：`admin.html`、`kb.html`、`review.html`、`topics.html`、`acceptance.html`、`acceptance_eval.html`、`acceptance_data.html`、`acceptance_errors.html`——删各自手抄 `topnav`，加 `data-page` 标记并引入 `admin-shell.js`。
4. `static/style.css`：管理端侧栏样式 + 区分配色 + 「管理端」徽标。

## 留给实现者
- 管理端侧栏样式与区分配色的具体取值(沿用现有翡翠绿+活力橙，管理端倾向更沉稳的深色系)。
- 「管理后台」入口在聊天页侧栏底部的具体样式与交互。
- 验收四页的激活态(统一归为「验收」高亮)。
