# 第七章「会话上下文管理」Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native)。Steps use checkbox (`- [ ]`) syntax.

**Goal:** 把 `_trim_history` 的简单裁剪升级成三层上下文管理(层1原文/层2截短/层3异步摘要),预算从窗口倒推、字数口径,每轮调模型前现场拼精简版,前端加多会话侧栏。

**Architecture:** 沿用 LangGraph 图。新增「预算+token 口径」「上下文拼装」「后台摘要任务」三个纯逻辑模块;`react_agent_node`/`resolve_coref`/`classify_intent` 改用拼装出的精简版;`conversation_id`/`user_id` 进 GraphState,`thread_id=conversation_id`;摘要走独立 asyncio 后台(每会话去重锁)。

**Spec:** `docs/superpowers/specs/2026-11-20-ch07-context-design.md`

## Global Constraints

- 技术选型定死:LangGraph State(add_messages+checkpoint)、LangChain `trim_messages`、MySQL。不换。
- 工具结果不落 messages 表(现状已如此);只存 user/assistant。
- 摘要后台异步,不阻塞当前轮;只追加不重写;触发看用量不数条数。
- 预算字数口径;`MODEL_CONTEXT_WINDOW` 默认 32768;标定常数锁死 5650/3954/1695。
- 用户身份 = 客户端 localStorage 稳定 user_id;conversation_id 与 user_id 解耦;thread_id=conversation_id。
- 梗概不单独占 system;拼装顺序 system→层2→层1→用户当前句→(梗概+证据)一条 HumanMessage。
- 前端 Vibe Coding;纯 prompt(摘要)用评估集替 TDD;确定性代码 TDD。
- 涉及 langchain trim_messages/SQLAlchemy 具体 API 已核实(trim_messages 签名见 langchain_core.messages.utils:1146)。

## Review Focus

1. **摘要不阻塞当前轮**:层2超预算 → 后台起摘要,当前轮回复照常返回(不 await 摘要)。
2. **装得下不压缩**:默认窗口 20 轮不触发降级/摘要(验收 3)。
3. **摘要不编造/不留寒暄**:只提炼事实诉求(评估集验)。
4. **梗概不占 system**:上下文里摘要只出现在用户句之后那条 HumanMessage。
5. **切会话重进图**:thread_id=conversation_id,checkpoint 空则回灌 MySQL 历史,能接着聊。
