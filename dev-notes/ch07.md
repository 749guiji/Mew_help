# 第七章「会话上下文管理」— 开发记录

## 阶段一:brainstorm 定稿(2026-11-20)

### 用户关键原话(需求要点)
- 用 Superpowers 把「第一版的简单裁剪」(agent 的 `_trim_history`)升级成正经上下文管理,只当前会话、不跨会话不存画像。
- 三层结构:层1原文/层2截短(用户原话不动、客服答复留开头几十字、工具结果一行标识)/层3异步摘要;两锚点 summary_upto_msg_id + layer1_from_msg_id,降级只挪 id 不搬数据;摘要单开 conversation_summaries 表一段一追加、不回头重写。
- 摘要后台异步:层2攒到超预算就起摘要,追加新段、边界追到层1起点,不阻塞当前轮;触发看用量不数条数;工具结果不落消息表;摘要只提炼事实诉求(商品/订单号手机号/诉求/未解决),不编不留寒暄,几十到一两百字。
- 拼装固定顺序:system(人设红线工具定义,每轮一样)→层2截短→层1原文→用户当前句→梗概+证据合成一条挂用户句后;梗概不单独占 system(前缀缓存)。
- 预算从窗口倒推不写死:扣系统提示/证据/梗概/输出预留/安全余量/ReAct 瞬时峰值;历史预算取 min(想留轮数×稳态,窗口匀得出来);层1七成层2三成;启动自检;中文字数折 token 口径和预算一起标定。
- conversations/messages 两表;State messages 挂 add_messages + checkpoint;完整历史与精简版各走各的。
- 可观测:每轮打 model_ctx(摘要全文+滑窗+条数+tokens)/history_ctx(摘要行+滑窗,每轮必打);摘要任务 trigger/start/done/skip/fail 留痕。
- 前端多会话侧栏 + GET /api/conversations、GET /api/conversations/{id}/messages。
- 验收:①20+轮不爆 ②演示配置(18000/2000/2000/3/1200/5)算出 5650/3954/1695,完整级联降级+摘要留痕,靠梗概答对「最开始那个订单」③默认窗口 20 轮不降级不摘要 ④日志看得到摘要压缩痕迹、grep model_ctx/history_ctx ⑤前端侧栏多会话切换回载。

### 关键产出(侦查结论)
- `_trim_history`(agent.py)是「简单裁剪」要替换;`_history_text`(nodes.py)是 coref/intent 共用历史。
- `chat_service` 已只存 user/assistant,工具结果不落消息表(与需求一致)。
- `app/core/jobs.py` 按作业名 key,不适合每会话摘要任务 → 用独立 asyncio 后台。
- config 无窗口/预算字段,要加;Conversation 无 summary 列。

### 我的自决(用户「可以」认可)
- 摘要任务 = 独立 asyncio 后台,每会话去重锁,失败留痕跳过。
- token 口径 = 中文字数×标定常数,和预算公式一起用测试锁死 5650/3954/1695。
- 摘要用主模型;想留轮数/默认窗口按验收 3 反推标定。
