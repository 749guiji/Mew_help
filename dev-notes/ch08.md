# 第八章「工具系统」— 开发记录

## 阶段一:brainstorm 定稿(2026-11-21)

### 用户关键原话(需求要点)
- 用 Superpowers 把写死的 6 个内置工具升级成「即插即用的工具系统」。七块:①注册中心(内置+MCP 统一三件套 name/描述/JSON Schema,内置启动时登记、MCP 现问现拿、新工具即用不改核心代码不重启)②参数校验(JSON Schema,拦下回灌模型不抛异常)③权限(读/写两类,写由引擎把门,本系统写操作只有 create_ticket,要等前端确认才执行;MCP 用途声明不可信,读/写只认我方规则)④执行引擎(统一管超时/重试/错误三分类/结果格式化,重试只给网络暂态、业务空不重试、写默认不自动重试)⑤审计 tool_audit_logs(每次调用落一条,含被拒被拦,不挂外键、写审计失败不拦执行)⑥MCP 接入(自建物流/售后两个业务 Server,Streamable HTTP,mock 数据不建表;Client 用 langchain-mcp-adapters 的 MultiServerMCPClient;内置 query_logistics 下线防重名)⑦建工单确认流(明确要求才走,Agent 核对必填缺则追问,凑齐发起 create_ticket,用 LangGraph interrupt 推工单预览,前端确认/取消;第 5 章投诉按钮建单路保持不动)。
- 技术栈定死:MCP Server 用官方 Python SDK 走 Streamable HTTP;Client 用 MultiServerMCPClient。本章不做 Skill 机制、不接仓储等更多系统。
- 验收:①新写工具只注册即可用 ②两个 Server 单独起进程、物流经 MCP 查到 ③Server 侧加工具只重启该 Server、客服侧不动不重启即可用 ④明确说建单但没讲清→Agent 追问→预览卡→确认落 tickets+回复带工单号 ⑤预览点取消不建单、审计=权限拒绝 ⑥人为超时看重试+兜底、审计重试次数/超时/耗时齐全;写操作超时不自动重试(retry_count=0)。
- 工作要求:全程 Superpowers;非可单测任务(TDD→标注样例/评估集);前端预览卡 Vibe Coding;过程留痕 dev-notes/ch08.md 每阶段补一段;库/框架/API 先 Context7 查;选型定死矛盾停下问。

### 关键产出(侦查结论)
- 现状:6 个 `@tool` 硬编码在 `app/tools/__init__.py`(`ALL_TOOLS`→`TOOL_REGISTRY` dict);`AGENT_TOOLS` import 时算好(去 query_faq/create_ticket),`react_agent_node` 每轮 `bind_tools` 用静态表。`ToolExecutor` 就 120s 超时+2 次无差别重试,无校验/权限/审计/分诊。
- `create_ticket` 当前不是 agent 工具(走前端 `/api/tickets`);`current_conversation_id` ContextVar 定义了但从没 `.set()`,死代码。`query_logistics` 内置要下线。interrupt 只在 `fetch_order` 节点用,resume 现传订单号字符串。
- Context7 核对 API(v1→v2 关键差异,避免返工):MCP SDK 的 `FastMCP` 已改名 `MCPServer`(旧 import 路径删除,`from mcp.server import MCPServer`),`mcp.run(transport="streamable-http", port=...)`;`MultiServerMCPClient(connections, tool_name_prefix=False, handle_tool_errors=True)`,连接配 `{"transport":"streamable_http","url":...}`,`await client.get_tools(server_name=...)` 返回 langchain 工具,旧 `async with MultiServerMCPClient(...)` 已删除;工具 `ainvoke` 返回 `(content, artifact)` 元组(content_and_artifact),`args_schema`=inputSchema。

### 用户裁定(我抛出、用户拍板)
- **路由**:「帮我建个工单」这类明确建单请求,现在被归「投诉」→安抚+按钮(不进 agent)。两条路,**用户选 A:新增「建工单」意图**,`_ROUTE_BY_INTENT["建工单"]="business"` 进 Agent;投诉安抚+按钮路不动。
- 附确认:① MCP 读/写 = 我方配置白名单、默认只读;② create_ticket 确认 resume 载荷结构化 `{confirm: bool}`。

### 我先定(用户无异议)
- builder check 7 问全部落为设计者自决,写进 spec §4/§5:①MCP 工具命名裸名不加前缀、`tool_name` 记裸名 `mcp_server` 记来源 ②MCP Server 宕机优雅降级(discover 跳过+记 warn,不缓存旧工具)③MCP 返回普通字符串、查询落空=正常返回不重试 ④并发:内置 registry 写一次只读、MCP 每轮 discover 返回新本地表不碰共享全局 ⑤create_ticket schema 收紧 description 非空 + ticket_type∈{售后,投诉,咨询} ⑥pending_ticket 存完整已校验 args ⑦tool_audit_logs 完整 DDL 逐字进 schema.sql。
- 架构「一个 registry + 统一引擎」只有一条正路(需求硬要求三件套统一登记),不列 A/B。
