# 第六章「分流器正式版」— 开发记录

## 阶段一:brainstorm 定稿(2026-11-20)

### 用户关键原话(需求要点)
- 用 Superpowers 把占位的分流器做成正式版,这是 Workflow 里最关键的节点。
- 六块:①指代消解+Query 改写(带指代补全成不依赖上下文的完整问题,已完整的原样透传)②Query 扩写(强制 JSON `queries[]`,只对退款退货/售后等高频容错低场景,检索侧现查现用,库里只留一份)③意图识别(LLM prompt 四件套:七类枚举选择题 + 强制 JSON `{intent,confidence}` + 边界 few-shot + 「其他」兜底)④分流精化(退款退货/售后走确定性子流程:拿订单→Query 扩写→强制检索政策→只把「这单能不能退」交主力 Agent)⑤槽位(缺订单号不猜、弹订单选择器回填;退款原因下拉自选)⑥前端(可点选订单卡片 + 退款表单)。
- 意图识别默认配「够格大模型」先做准,成本吃紧走降级:小模型给判断+置信度,置信度低才升级大模型重判。
- 本章不做:微调小模型 / BERT 意图分类;跨会话记忆。
- 验收:①多轮(物流→退款→物流)每轮意图判对+指代补全对 ②JSON 稳定可解析、怪问题落「其他」③「这个能退吗」先补全指代再走退款子流程 ④不带订单号问退款弹订单选择器、点选后走完。
- 要求:Superpowers 全流程;非可单测任务(TDD→标注样例/评估集跑验证);前端 Vibe Coding 直接做;Context7 查库用法;技术选型定死、矛盾停下问。

### 关键产出(侦查结论)
- 现有占位:`resolve_coref`(透传)/ `classify_intent`(纯文本+子串匹配)/ `route_from_intent`(七类四出口硬编码)。
- 图:`reset→coref→intent→{knowledge/business/complaint/chitchat}→...→log`(`app/graph/build.py`)。
- `query_understanding.py` 已有检索侧 `rewrite_query`(`with_structured_output(method="function_calling")` + Ollama 兜底)。
- 意图评估基建:`scripts/eval_intent.py` 跑 `tests/data/intent_samples.json`(8 条单轮,无指代/无多轮)。
- **无订单/退款数据**:`query_order` 是 mock 随机;`db/schema.sql` 明写「商品、订单、物流走工具内 mock,不建表」。
- **无大模型配置**:`.env` 仅 `model=qwen3:8b`。
- `content_type` 取值 `faq/policy/manual`(`return-policy.md`→policy);Milvus 检索侧 filter 目前只用在 `category` 字段。

### 用户裁定(我抛出、用户拍板)
- 订单数据:**A = 固定种子 mock 列表**(进程内常量,不建表,`GET /api/orders` + `query_order` 改查它)。
- 大模型:**③ 本地只有 qwen3:8b**,`intent_model` 默认= `model`,降级路骨架搭好,后续项目完整再走云端 API 测试。

### 我先定(用户无异议)

- 「其他」意图路由 → `business`(进 Agent 通用回应,置信度低)。

### 关键产出
- 设计文档:`docs/superpowers/specs/2026-11-20-ch06-router-formal-design.md`(已写,builder check 通过,待用户批准)。
