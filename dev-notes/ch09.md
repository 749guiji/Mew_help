# 第九章「可观测性与数据飞轮」— 开发记录

## 阶段一:brainstorm 定稿(2026-11-21)

### 用户关键原话(需求要点)
- 用 Superpowers 给客服系统装「眼睛」+ 把「答不上」变「改进燃料」。六块:①Langfuse(设 env、LangGraph 编译时挂一次回调,完整 trace 树可铺开看)②Cost Control(意图识别结果进 trace 元数据,按意图统计 token 花销)③数据飞轮三入口(检索置信度低 / 生成自评不足 / 用户点 👎)都送进 ch04 的 low_confidence_questions 池,标 source + 存当轮召回片段快照(新加一列),👎 事后落池从该轮检索尽力回捞、真没走检索才空着 ④飞轮流水线(标准化→查重→入 review_queue 待审,命中累加 occurrence_count 不新建行,归并落点记 matched_review_id;人工审核通过走 ch03 落库)⑤评估流水线(复用 ch04 评估集+指标,每轮落 eval_runs 看趋势)⑥前端待审队列后台页(列表/详情/通过/驳回)。
- 技术栈定死:Langfuse 开源自部署、数据不出本机。本章不做低置信度按主题归类的微调分类器。
- 验收:①Langfuse 点开任意请求看完整链路 ②问知识库没有的问题→兜底+待审队列出现+详情看得到原话和召回片段 ③后台点通过后再问同问题能答对 ④点 👎→落池→标准化查重→待审队列 ⑤能拿出按意图汇总的 token 花销 ⑥评估流水线跑两轮看趋势。
- 工作要求:全程 Superpowers;非可单测任务 TDD→标注样例/评估集;前端 Vibe Coding;留痕 dev-notes/ch09.md 每阶段补;库/框架 API 先 Context7 查;选型定死矛盾停下问。

### 关键产出(侦查结论)
- **两点与需求不符**:①生成阶段自评 `self_check()` 在 `generation_quality.py` 里定义了但**全仓库无调用点**,是死代码,「ch04 已经在落池」不成立,要真正接进图。②👎 反馈 `addFeedback` 是纯前端(点亮锁住),不发请求到后端。
- 闸是最简版:`gate_node` 就是 `retrieval_score >= threshold`(ch05 的 gate_pass),要升级成 evidence_confidence。检索信号够用:`retrieval_chunks` 的 `ScoredChunk.score` 是 rerank 后分,Top1 分/分差/有效条数都能算。
- `retrieval_chunks` 只在进程内 InMemorySaver checkpoint、每轮 `_reset_node` 清空、不落库 → 👎 快照没有持久来源(→ 改为重跑检索)。
- Langfuse 挂点:`build_graph()`/chat_service `config`;评估侧 `run_eval.py` 是 CLI,要包成能落 eval_runs 的函数。
- Context7 被墙(memory 一致),WebSearch 兜底核到 Langfuse v3:`from langfuse.langchain import CallbackHandler`(旧 `langfuse.callback` 已迁),config `callbacks=[handler]` 挂载,`langfuse_user_id/session_id/tags` 元数据键,**v3 回调仍是同步实现、async 图有阻塞/漏记风险**。

### 用户裁定(我抛出、用户拍板)
- **Langfuse 自部署方式**:代码配好 env+回调 + 交付 `langfuse/docker-compose.yml`,用户本地 `docker compose up` 起(不把整套编排塞主 compose)。
- **飞轮触发**:手动 job(`/api/jobs/flywheel` + CLI),不搞定时。
- **self_check 落点**:独立 `self_check` 节点(知识类 `agent → self_check → log`)。
- **self_check 语义(用户选 A)**:事后判断 + 落池、**不拦已流出的答案**——ch08 答案边生成边流式,agent 后节点无法「拒答」已发出的答案;故 self_check 只判证据够不够、不够就落池,不改用户已收到的答案、不追加拒答话术。备选「前置闸」会退掉知识类流式,弃。

### 翻车与返工(按严重度)
- **langfuse 版本大反转(第一大坑)**:WebSearch 说的是 v3 API,实际装到 **5.2.0(v5)**。v5 的 `CallbackHandler` 从 `langfuse.langchain` 导入、**没有** `langfuse_user_id/session_id/tags` 配置键、**没有** `update_current_trace`。意图按维度聚合的 tag 机制缺失——先只挂回调拿 trace 树 + 记 intent 日志,聚合留后续(ledger)。
- **pydantic v2 BaseModel 不吃位置参数**:测试里 `SelfCheckResult(False,...)` 写错,monkeypatch 抛 TypeError 被节点吞掉,排查后改关键字参数。
- **知识类图测试打到 self_check 真 LLM**(加 autouse 假函数),全量耗时从 79s 回到 24s。
- **SQLite :memory: + TestClient 多线程**:feedback/review 测试同 ch08 的坑,用 StaticPool 共享单连接。
- 存量库缺 ch07 三列 + tickets「退款」枚举(环境遗留),迁移时手动 ALTER 补齐。
